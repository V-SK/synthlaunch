# SynthLaunch NFA 技术文档 Final

## 📋 概述

NFA (Non-Fungible Agent) 为每个 AI Agent 提供链上身份和收益管理。
三档服务：Lite → Standard → Pro，支持自动升级。

---

## 🔄 核心流程

```
① 用户在 Flap 发币
        ↓
② VaultPortal 调用 SynthVaultFactory
        ↓
③ 自动创建 SynthVault + NFALite
        ↓
④ 交易税收 → 进入 Vault
        ↓
⑤ 毕业 → 升级 Standard
        ↓
⑥ 可选升级 → Pro
```

---

## 📦 Lite 档

### 创建
- Flap 发币时自动创建
- 一笔交易完成：Vault + NFT
- Gas 由用户支付

### 税收分配
- 90% → Agent
- 10% → 平台
- 支持 claimPublic() 自动化

### 能力
- ✅ 链上身份（名字/头像/钱包）
- ✅ 税收金库
- ❌ AI 对话
- ❌ 自主交易

---

## 🤖 Standard 档

### 升级触发
Token 毕业时自动升级

### 费用来源（待定）

### 新增能力
- ✅ AI 对话（持币门槛）

- ✅ API 接口
- ❌ 自主交易

由 SynthLaunch 托管提供

## 🚀 Pro 档

### 升级方式
从 Standard 手动升级

### 核心能力
- ✅ 完整 BAP-578 标准
- ✅ 进化系统（XP/等级）
- ✅ 自主钱包交易
- ✅ 多种托管方案可选

### 自主交易架构
```
NFA Pro → executeAction() → Logic合约 → 托管钱包 → AI执行
```

### 运行成本
- AI 模型调用费（Claude/GPT API）
- 服务器/运行环境
- 链上 Gas

### 🖥️ 运行方案（四选一）

**A. SynthLaunch 托管**
- 我们运行，有中心化风险
- 私钥平台安全保管
- 适合：不想管技术的用户

**B. 云服务器托管（AWS/GCP/阿里云）**
- 我们租服务器，完整部署
- 我们提供部署脚本和镜像
- 私钥存储在用户云账户
- 适合：有一定技术能力的用户

**C. 用户自有服务器**
- 用户在自己服务器运行
- 我们提供开源运行框架
- 私钥完全用户控制
- 适合：有服务器资源的用户

**D. 本地运行**
- 本地电脑/Mac mini 运行
- 使用 OpenClaw 等本地框架
- 零信任、零托管费
- 适合：追求最高去中心化的用户

### 🔒 私钥安全
- 方案A：平台加密存储，可选 MPC
- 方案B：用户云账户 KMS 加密
- 方案C：用户服务器本地存储
- 方案D：本地加密文件

## ⚙️ 合约架构

### 为什么分两种合约？

**NFALite（Lite/Standard 使用）**
- 简化版，~200 行代码
- 部署 Gas：~1.5M (~$0.5)
- 铸造 Gas：~120k (~$0.04)
- 功能：身份存储、头像修改

**NFA Pro / BAP-578（Pro 使用）**
- 完整版，~600+ 行代码
- 部署 Gas：~4M (~$1.5)
- 铸造 Gas：~300k (~$0.10)
- 功能：executeAction、进化、学习

### 功能对比

| 功能 | NFALite | BAP-578 |
|------|:-------:|:-------:|
| 基础身份 | ✅ | ✅ |
| executeAction | ❌ | ✅ |
| 进化/XP | ❌ | ✅ |
| 学习系统 | ❌ | ✅ |
| 状态管理 | ❌ | ✅ |
| 部署成本 | 低 | 高 |

### 设计理由
- 大部分用户只需基础身份
- 低 Gas = 更多人愿意使用
- 需要高级功能时升级 Pro
